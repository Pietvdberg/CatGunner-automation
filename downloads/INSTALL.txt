CatGunner AutoPilot 0.4.7 — Pixel 10 / Android 16

The APK is signed with the same development certificate as previous versions.
It includes offline OCR. It does not disable or bypass Play Protect.

Ubuntu update (using the Platform-Tools folder from the previous installation):
  cd ~/Downloads
  ./platform-tools/adb devices
  ./platform-tools/adb install -r ~/Downloads/AutoPilot-Pixel10-0.4.7.apk

Connect the unlocked phone over USB with USB debugging enabled; accept the
phone's debugging prompt. Keep Play Protect enabled. If ADB reports an error,
copy its exact output. Do not install developer tools on a work computer where
running them is not permitted. USB is not required during normal app use.

Calibration is retained. Enable accessibility until AutoPilot says Connected,
then start/resume user-consented capture. Manual single-purchase tests still work.

NEW: Bounded automatic run
- Choose a cap of 1, 3 or 5 purchases (default 3).
- For a first deterministic check, choose Rotate Power / Speed / Money.
- Start the bounded run; the app opens the game. Keep its upgrade bar visible.
- Every purchase must be VERIFIED before another request can be armed.
- The run stops at its cap, or earlier on failure/uncertainty/interruption.
- Pause/Stop or returning to AutoPilot stops the run. Resume only resumes
  observation; it never starts automatic purchases.
- UNCONFIRMED means a purchase may already have occurred: inspect the game and
  use the review button before arming another test or starting another run.
- Lowest comparable price only ranks exact amounts with identical suffixes;
  differing suffixes stop that rule because their scales are not established.
- Rotation does not compare prices. No expected-DPS or rebirth optimizer exists yet.

The owner validated single purchases for all three controls with VERIFIED 2/2.
The owner validated a complete 5/5 run on 0.4.1; the new focused OCR path
still needs phone validation.
Green banknotes only; gems, unknown currency and real money remain forbidden.
Use Copy test diagnostics if a run stops unexpectedly; no data uploads automatically.

0.4.1 changes: transient stale OCR/frame or label checks before a tap can wait
for two new readings within the ORIGINAL deadline. No accepted or refused actual
gesture is retried. Preparation tokens prevent late old jobs from acting. Copy
diagnostics now includes the exact dispatch block, frame ages and actual callback.
Keep the game visible until the new Automatic run complete/stopped alert instead
of returning after a fixed 30 seconds. Alerts require allowed notifications and
may be silenced by Android settings or Do Not Disturb. Opening AutoPilot or its
notification shade mid-run still stops foreground-only operation.

0.4.2 changes: only six level/price fields go to OCR, at their native resolution.
Full calibration-preview copying pauses while purchasing. Frame checks run up to
10 Hz while purchasing (4 Hz otherwise); only one OCR task can run at a time.
All purchase guards and two-sample verification remain. Completion shows total
run seconds including game opening. Copy diagnostics includes OCR work time and
readable sample counts. No measured phone speedup is claimed yet. Try the same
five-purchase rule to compare; keep the game visible until the outcome alert.

0.4.3 changes: each armed purchase has its own timing record. After a run, inspect
numbered rows #1-#5 or use Copy test diagnostics. Each shows total, selection,
readiness, preparation, callback and verification milliseconds plus per-purchase
OCR average/max times, readable/stale counts and evidence deferrals. Missing stages
show a dash. The first selection includes game opening. Preparation includes any
unsent evidence rechecks. Pre-arm frames are excluded from OCR counts. Failed and
unconfirmed armed requests keep timing too. Start a new run to reset the list.
Do not return to inspect timings while the run is active; wait for its outcome.

0.4.4 fixes the no-action OCR regression: the six packed fields from 0.4.2/0.4.3
are removed. Recognition uses the original full upgrade strip and coordinate
mapping from the phone-validated 0.4.1 build. Per-purchase timing stays enabled.
Calibration stays saved. Start/resume capture and explicitly start a new run;
keep the game visible until its outcome notification. Native recognition must
be rechecked on the phone. No purchase guard or strict level parser was relaxed.

0.4.5 reduces repeated OCR: fresh frames with exactly identical level/price pixels
can recheck a recent full-strip interpretation without repeating native inference.
Changed text still uses the same full-strip OCR as 0.4.4. All two-frame purchase
checks remain. Actual gestures invalidate reuse. Per-purchase rows show pixel
recheck counts and native OCR timings separately. Test the same three-purchase
rule and wait for completion before copying diagnostics. Calibration is retained.
Phone speedup and live recheck hit rate are not established by cloud tests.

0.4.6 keeps valid observations when an intervening OCR result is incomplete;
partial text never counts as confirmation or sends a gesture. Unknown actual UI
still resets evidence. Original time limits and two complete frame observations
remain. Pixel comparison excludes non-text background/icons, with exact equality
and mandatory token-box coverage. Copy diagnostics now retains cache rejection
counts and up to four preparation deferral reasons for each purchase. Phone speed
and hit rate need testing. Inspect any UNCONFIRMED purchase before starting again.

0.4.7 removes the ineffective pixel cache. Native OCR uses a dedicated worker,
with result parsing off the main thread and idle work throttled. The same full
strip image is used. Small Lv. marker errors can be accepted only after pixel
geometry proves the dot and the recognized digit count; digits/prices are never
reconstructed. Timing rows split copy/SDK/parse/main handoff and show worker
priority. All currency, freshness, verification and run limits remain. Calibration
is retained. Native fixture checks cannot establish actual Pixel 10 speed.

Automatic purchase boundaries can reuse the final verified frame as ONE initial
precondition, with its original timestamp and a 750 ms age limit. A newer second
complete frame and that target's banknote proof are still required. This removes
one redundant full OCR wait between verified purchases, without batching taps.
