CatGunner AutoPilot 0.3.3 — Pixel 10 development installation

This archive contains the signed arm64 APK and these instructions.
The APK is the same file previously provided, not a Play Protect fix.

1. Extract this ZIP on your computer.
2. Get Google's Android SDK Platform-Tools for your operating system:
   https://developer.android.com/tools/releases/platform-tools
3. On the phone, enable Developer options and USB debugging in Android settings.
4. Connect the phone by USB and accept its debugging authorization prompt.
5. Open a terminal in the platform-tools folder. Use adb devices to confirm access.
   Windows PowerShell: .\adb.exe devices
   macOS/Linux: ./adb devices
6. Install the extracted APK using its actual path:
   Windows PowerShell: .\adb.exe install -r "C:\path\to\AutoPilot-Pixel10-0.3.3.apk"
   macOS/Linux: ./adb install -r "/path/to/AutoPilot-Pixel10-0.3.3.apk"
7. Keep Play Protect enabled. If installation is still blocked, report the actual
   installer/ADB error; do not alter the APK to disguise its capabilities.
8. Disable USB debugging after installation if it is no longer needed.

After installation, use the in-app setup instructions. Android accessibility and
screen-capture grants must be completed on the handset. The computer is not
needed during normal app use. This is a single-purchase test build; physical OCR
and purchase verification still require testing. Only green banknotes are allowed.
Gems, unknown currency and real-money purchases are forbidden.

Version 0.3.3: calibration is retained. Check that accessibility says Connected.
If it says Enabled but disconnected, toggle AutoPilot off and back on in Android
accessibility settings. Run one new test. If it fails, press Copy test diagnostics
and paste the text into the chat. No diagnostics are uploaded automatically.

0.3.3 accepts the observed Lvo166/Lvo167 fixed-prefix OCR separator without
substituting any numeric digits. Existing calibration is retained. Timeout
details now include the last blocking stage. Copy diagnostics if a test fails.

0.3.3: one actual tap may succeed even if a later frame cannot be verified.
Keep the game visible for about ten seconds after the tap. The verifier gets a
fixed eight-second window without another gesture. VERIFIED still requires two
matching post-completion level increases. UNCONFIRMED means a purchase may have
happened: inspect the game and use its explicit review button before any new test.
Never repeat a test solely because the purchase could not be verified.
